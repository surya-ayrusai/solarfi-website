# Contact Us → n8n → Supabase + Google Sheet (Phase 1)

How a website inquiry becomes a lead, and how to set it up, change it and test it.

```
Contact Us form (contact-us.html + contact-form.js)
  │  POST JSON, header x-solarfi-key
  ▼
n8n "Solarfi Inquiry Intake" (webhook /webhook/solarfi-inquiry)
  Intake Config → Security Gate (key 401, origin 403, rate limit 429, honeypot 200)
  → Validate & Normalise (422 + field errors)
  → Request Already Seen? (same client_request_id → 200 with original lead_id)
  → Same Mobile in 24h? (sets is_duplicate) → Derive Lead Fields (kW estimate, ids)
  → Call Queue Property? → Mark Call Queue / Mark Site Visit Queue → Merge Enquiry Queues
  → Insert Lead (Supabase, 1 retry) → Append Enquiry to Sheet → 200 { ok, lead_id }
  → Build Lead Notification → Email Team: New Lead + WhatsApp Uday (after the response; failures here never affect the visitor)
  Supabase fails → re-check → email alert → 500.  Sheet fails → email alert → still 200.
```

n8n Starter has no Variables, so settings live in the first node of the workflow. None of them are secrets.

## The form key

- It is generated locally into `.env.local` (gitignored) as `SOLARFI_FORM_KEY`, with its hash as `SOLARFI_FORM_KEY_SHA256`.
- **It is visible to every visitor's browser**, because the browser has to send it. Treat it as a spam filter, not a secret. The real protection is the server-side validation, the origin allowlist, the rate limit and the honeypot.
- **The key is committed in `lead-form-config.js`** (decided 2026-11-06). This repo has no build step (Vercel serves the folder as-is), so the value has to be in the deployed file, and it is public either way.
- **To rotate the key:** generate a new one, put its SHA-256 in Intake Config → `FORM_KEY_SHA256`, and deploy the new key in `lead-form-config.js` at the same time.

```bash
K=$(openssl rand -hex 24); printf %s "$K" | shasum -a 256
```

## Supabase

- Run `supabase/migrations/20261106_create_leads.sql` in SQL Editor. It is safe to re-run.
- `public.leads` has RLS on and **no policies**, and `anon` and `authenticated` have no grants. Only n8n's service role can read or write it.
- Phase 2 should add an authenticated-admin `select`/`update` policy. The `/admin` dashboard in this repo currently queries a different `leads` shape (`supabase/schema.sql`, never run) and will need adapting to these columns.
- `public.quotes` was not touched.

## Running the tests

```bash
node --test tests/*.test.mjs
```

```bash
set -a; . ./.env.local; set +a; tests/e2e/api-tests.sh
```

- The first runs the offline tests: validation rules and the n8n Code nodes, in a stand-in for n8n's runtime.
- The second runs the live API tests (statuses, routing, honeypot, duplicates, idempotency). Its test leads use names starting with `Etest` and mobiles `+91 90000 000xx`.
- **Rate limit:** the e2e script makes more than 5 calls. To run it, set `RATE_LIMIT_PER_HOUR` to 100 in Intake Config first. Afterwards, set it back to 5 **and bump `RATE_LIMIT_EPOCH`**. Otherwise anyone sharing your internet connection (office Wi-Fi) is blocked for up to an hour.
- **Forced failures (T9/T10):** set `LEADS_SHEET_ID` to a wrong value (Sheet failure), or point `Insert Lead (Supabase)` at `/rest/v1/leads_FORCED_FAILURE` (Supabase failure), submit once, then restore.
- **Browser test locally:** serve the folder on `http://localhost:3000` with the key filled in, and temporarily add `http://localhost:3000` to **both** origin settings. Remove it afterwards.

## Known deviations from the brief

1. **Malformed JSON returns 422, not 400.** n8n Cloud rejects unparseable JSON bodies itself (`422 "Failed to parse request body"`) before the workflow runs, so nothing is written. It can't be changed from inside the workflow.
2. **Variables become a config node.** The n8n Starter plan has no Variables (limit 0), so `UNITS_PER_KW_PER_MONTH` and the other settings are in **Intake Config**. Upgrading the plan would allow moving them to `$vars`.
3. **New table, not `"quote-chase-board"`.** `"quote-chase-board"` is the Supabase project name. Its only table, `quotes`, conflicts with the lead model, so leads go to a new `public.leads` table. This was approved on 2026-11-06.
